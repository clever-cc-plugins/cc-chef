# Export formats

Use this file when `export-recipe` turns a finished recipe into something another app can take in, and when it explains to the user which target to pick and what will be lost on the way. It covers the two files the plugin writes (schema.org Recipe JSON-LD and the Paprika `.paprikarecipes` archive), how receiving apps read them, which apps take which route, and the formats the plugin deliberately does not write. The Tandoor API reference arrives in phase 2 as `tandoor-api.md`; this file holds no Tandoor endpoints or request shapes. Section 1 sets the output strategy, section 2 the JSON-LD profile, section 3 the Paprika archive, section 4 ingredient-line conventions, section 5 the app matrix, section 6 formats not written, section 7 what the user is told, section 8 the evidence notes.

Conventions: `(to verify)` marks a claim that only one research report made, or one the reports contradict without a tie-breaker. "Default" is what the plugin does when reports disagree. Evidence tags: documented = vendor docs, specification or release notes quoted by at least one report; source = read from a repository or serializer; community = third-party tool or forum, not the vendor; design = a rule chosen for this plugin. App status was checked by the reports on 1 November 2026 and changes quickly; treat every status cell as a snapshot.

## 1. Output strategy

### 1.1 What the plugin writes

| Output                                                                                    | Form                                                   | Reaches                                                                                                                                                       | Default role                                                                                                                                                 |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| schema.org Recipe JSON-LD                                                                 | `.json` file, one top-level `Recipe` object            | Apps with a paste or file route for structured data (Mealie, Crouton, RecipeSage, Nextcloud Cookbook via API or folder) and anything that reads a recipe page | Canonical file; every other output is rendered from the same internal recipe                                                                                 |
| HTML page with the same JSON-LD embedded in a `<script type="application/ld+json">` block | `.html` file the user can host or serve                | Apps whose only route is URL import (several consumer apps and self-hosted managers)                                                                          | Optional companion to the JSON file; needs a place to be served, so offered only when the user wants it No converter writes it; produced by hand on request. |
| Paprika archive                                                                           | `.paprikarecipes`                                      | Paprika, AnyList, Mealie, Tandoor, RecipeSage and others (section 5)                                                                                          | Second file; the closest thing to a shared exchange format among consumer apps                                                                               |
| Plain-text recipe card                                                                    | Markdown or text, headings and one line per ingredient | Any app with a paste field                                                                                                                                    | Fallback when nothing else fits (design, one report suggests it) No converter writes it; produced by hand on request.                                        |

### 1.2 Principles

| Principle                                  | Detail                                                                                                                                                                                                                                                                     |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One internal model, several renderers      | Keep the recipe as structured data (ingredient groups, quantity, unit, food, note; instruction sections; yield; times; language) and render each target from it. Do not treat the flat JSON-LD ingredient strings as the master copy (design; Claude and Perplexity agree) |
| A URL route is not a file route            | An app that imports from a web address does not necessarily open a standalone JSON-LD file. Say which route a target supports before promising it (documented)                                                                                                             |
| Fidelity differs by route                  | Native API or native archive keeps the most (ingredient groups, typed units, images); JSON-LD keeps metadata well but flattens ingredients; Paprika keeps text and colon headings; plain text keeps least (documented, all four reports)                                   |
| No invented data                           | Leave out `image`, `nutrition`, `author` or ratings rather than fabricate them; a valid recipe without an image is better than a fake one (design; Perplexity)                                                                                                             |
| Ingredient sections are the commonest loss | schema.org has no ingredient grouping; each app handles groups its own way. Tell the user when a recipe has groups and the chosen target drops them (section 7)                                                                                                            |
| API push is out of scope for phase 1       | Native adapters give the best fidelity but need per-instance verification. Phase 1 writes files; Tandoor API details come in phase 2 (design)                                                                                                                              |

## 2. schema.org Recipe JSON-LD

### 2.1 Fields and how the plugin fills them

| Field                               | Form                                        | Plugin default                                                                                                                                         | Why / quirk                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `@context`, `@type`                 | `"https://schema.org"`, `"Recipe"`          | Always set, as one top-level object, not inside `@graph`                                                                                               | Parsers handle a single top-level `Recipe` most reliably; `@graph` wrappers are usually unwrapped but were not tested (Claude; to verify)                                                                                                                                                                                            |
| `name`                              | String                                      | Required; non-empty                                                                                                                                    | Google rich results require `name` and `image`; no importer should be given a recipe without a title (documented)                                                                                                                                                                                                                    |
| `image`                             | Absolute HTTPS URL, array, or `ImageObject` | Only when the user supplies a real image URL; otherwise omit                                                                                           | Base64 data URIs are not portable in JSON-LD; they belong in formats that define them, such as Paprika. Google suggests several aspect ratios (1:1, 4:3, 16:9). An importer given an array tends to take the first image (documented / source)                                                                                       |
| `description`                       | Plain text                                  | One or two sentences                                                                                                                                   | Keep method out of it                                                                                                                                                                                                                                                                                                                |
| `recipeIngredient`                  | Array of plain strings                      | One string per ingredient in the order `quantity unit food, note` (section 4)                                                                          | Every importer reads this; structured `PropertyValue` or `ItemList` ingredients are permitted by schema.org but no app evidence shows support, and Google documents text (documented). Group headings do not belong here                                                                                                             |
| `recipeInstructions`                | Array of `HowToStep` objects with `text`    | Use `HowToStep` always; wrap in `HowToSection` (with `name` and `itemListElement`) only when the recipe has real sub-recipes such as dough and filling | Plain text blocks get split heuristically; explicit steps import more reliably. `recipe-scrapers` flattens sections into one step list, so section names may be lost downstream. Do not put "Step 1" or "Directions" labels in the step text (documented)                                                                            |
| `recipeYield`                       | Text or number                              | A single string with the number of servings, `"4"`                                                                                                     | Google prefers a plain serving count and allows extra yields in an array (for example `["4", "4 servings"]`); the plain string is the safest common denominator. Reports differ on whether to add a text form; default is the plain number, and a second text entry only when the yield is not servings (for example `"24 cookies"`) |
| `prepTime`, `cookTime`, `totalTime` | ISO 8601 duration                           | `PT15M`, `PT1H30M`, `P1D`; never display strings, never ranges                                                                                         | Google does not support time ranges. Include resting or chilling in `totalTime` when it is elapsed time (documented)                                                                                                                                                                                                                 |
| `nutrition`                         | `NutritionInformation`                      | Omit unless the recipe carries values from the nutrition workflow; then per serving, with units, and set `recipeYield`                                 | Google requires a serving yield when calories are given; apps differ on per-serving vs per-recipe (a Tandoor importer asks the user to choose) (documented)                                                                                                                                                                          |
| `recipeCategory`, `recipeCuisine`   | Text                                        | Not emitted by the converter (tags go to `keywords`); add by hand only on request                                                                      | Google advises not repeating these values in `keywords` (documented)                                                                                                                                                                                                                                                                 |
| `keywords`                          | Comma-separated text                        | Dietary and occasion tags, not category or cuisine                                                                                                     | A comma-separated string is the form importers read as tags (documented)                                                                                                                                                                                                                                                             |
| `inLanguage`                        | BCP 47 code                                 | Always set, for example `"de"` or `"de-DE"`                                                                                                            | Few importers read it, so do not rely on it for ingredient parsing; it still costs nothing and helps AI-based parsers (Claude, Perplexity agree)                                                                                                                                                                                     |
| `author`, `datePublished`           | Person or Organization; ISO date            | Not emitted by the converter; attribution travels in `isBasedOn`                                                                                       | Preserve known provenance                                                                                                                                                                                                                                                                                                            |
| `isBasedOn`                         | `CreativeWork`                              | Emitted when `source` or `source-url` exists: `{"@type": "CreativeWork", "name": <source>, "url": <source-url>}`, leaving out whichever is missing     | None of the four reports covers this property; it is a schema.org property chosen here to carry "adapted from" attribution (design; to verify that importers keep it, expect most to ignore it)                                                                                                                                      |
| `identifier` / `url`                | `urn:uuid:` string / URL                    | Optional stable id so a re-export can be matched                                                                                                       | Do not assume the receiving app de-duplicates on it (Perplexity)                                                                                                                                                                                                                                                                     |

### 2.2 Minimal profile

A complete example the converter can target (illustrative; no app-tested reference file exists):

```json
{
  "@context": "https://schema.org",
  "@type": "Recipe",
  "name": "Quick lentil soup",
  "inLanguage": "en",
  "recipeYield": "4",
  "prepTime": "PT10M",
  "cookTime": "PT25M",
  "totalTime": "PT35M",
  "keywords": "vegetarian, one pot",
  "recipeIngredient": [
    "200 g red lentils",
    "1 l vegetable stock",
    "1 onion, diced"
  ],
  "recipeInstructions": [
    { "@type": "HowToStep", "text": "Soften the onion in a little oil." },
    {
      "@type": "HowToStep",
      "text": "Add lentils and stock, then simmer until the lentils fall apart."
    },
    {
      "@type": "HowToStep",
      "text": "Season with salt and lemon juice before serving."
    }
  ]
}
```

### 2.3 Required vs recommended

| Layer                 | Requires                                                                                                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| schema.org vocabulary | No fixed mandatory set for recipe managers                                                                                                                                                                   |
| Google rich results   | `name` and `image`; recommends author, dates, description, keywords, category, cuisine, ingredients, instructions, yield, times, calories, rating, video. If calories are given, a serving yield is required |
| Recipe managers       | In practice `name`, `recipeIngredient`, `recipeInstructions`; the Google floor is not the plugin's target                                                                                                    |

### 2.4 Parser behaviour and known quirks

| Quirk                                            | Effect                                                                                                                                                                  | What the plugin does                                                                            |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Importers read the URL, not necessarily the file | Tandoor relies on `recipe-scrapers` for web import and fails on pages without embedded JSON-LD unless a custom scraper exists (a maintainer statement quoted by Claude) | When a user needs a URL route, produce the HTML page with the JSON-LD embedded                  |
| Ingredient groups lost                           | `HowToSection` covers instructions only                                                                                                                                 | Drop headings from `recipeIngredient`; keep groups in Paprika and tell the user                 |
| Heading line inside `recipeIngredient`           | Likely parsed as an ingredient (Perplexity, DeepSeek)                                                                                                                   | Never emit `"For the sauce:"` into the array                                                    |
| Parsers are English-trained                      | NLP ingredient parsers degrade on EL, TL, Prise, Bund, decimal commas and non-Latin text (documented in Mealie discussions; Tandoor issue on Japanese lines)            | Follow the line conventions in section 4; where the app offers AI parsing, point the user to it |
| Ranges                                           | Inconsistent: first number only, lost, or turned into a note                                                                                                            | The converter exports the line as written; check the first import                               |
| Import from Nextcloud `recipe.json`              | Tandoor's Nextcloud importer once mishandled `HowToStep` objects (issue #2428, Claude only, to verify for current versions)                                             | Not a plugin target; noted for users migrating                                                  |
| `NaN` quantity or unit in Nextcloud Cookbook     | Imported lines can show `NaN` until edited (DeepSeek only, to verify)                                                                                                   | Warn when the target is Nextcloud and the ingredients were free text                            |
| Google calories without yield                    | Validation error                                                                                                                                                        | Set `recipeYield` whenever `nutrition.calories` is present                                      |
| Keywords stuffed with category or cuisine        | Google warns against it                                                                                                                                                 | Keep fields separate                                                                            |
| Time ranges and text durations                   | Not supported                                                                                                                                                           | ISO 8601 only                                                                                   |
| Image arrays                                     | First image taken                                                                                                                                                       | Put the best image first                                                                        |
| Recipe Keeper                                    | Exports schema-tagged HTML; JSON-LD import not verified                                                                                                                 | Do not offer JSON-LD for Recipe Keeper (DeepSeek, Perplexity; to verify)                        |

## 3. Paprika `.paprikarecipes`

### 3.1 Container

| Aspect            | Fact                                                                                                                                             | Evidence                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| Outer file        | A ZIP archive named `*.paprikarecipes`                                                                                                           | documented (Paprika guide, Tandoor import docs)                     |
| Members           | One file per recipe, extension `.paprikarecipe`, each a gzip-compressed JSON document                                                            | documented; all four reports agree on the zip-of-gzipped-JSON shape |
| Single recipe     | A lone `.paprikarecipe` file is also an import format                                                                                            | documented (Paprika lists both extensions)                          |
| Alternative input | Paprika also reads a simpler documented YAML format with `name`, `ingredients` and `directions` required                                         | documented (Claude, Perplexity); the plugin does not write it       |
| Version scope     | The guide describes Paprika 3; a Paprika 4 beta adds features that must not be assumed for version 3                                             | documented (Perplexity)                                             |
| Round trip        | Not tested against current app builds by any report; Perplexity advises writing the smallest valid subset first and testing before adding fields | design                                                              |

### 3.2 Recipe fields

Each member is one JSON object. The plugin sets the fields in the first group and leaves the rest out unless noted.

| Field                                  | Content                                                                                | Plugin default                                                                                                                                                                   |
| -------------------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `uid`                                  | Unique id string                                                                       | New UUID per recipe                                                                                                                                                              |
| `name`                                 | Title                                                                                  | Required                                                                                                                                                                         |
| `ingredients`                          | One text block, ingredient lines separated by newlines                                 | Required; section headings as lines ending in `:` (3.3)                                                                                                                          |
| `directions`                           | One text block, steps separated by newlines                                            | Required                                                                                                                                                                         |
| `servings`                             | Text, the bare yield from the recipe, for example `4`; the converter adds no unit word | From the recipe yield                                                                                                                                                            |
| `prep_time`, `cook_time`, `total_time` | Free text such as `15 min`                                                             | Human-readable text, not ISO 8601; the reports do not state the accepted format, so keep it plain (to verify)                                                                    |
| `description`                          | Short summary                                                                          | Optional                                                                                                                                                                         |
| `notes`                                | Free text                                                                              | Variations, storage, caveats                                                                                                                                                     |
| `source`, `source_url`                 | Attribution name and link                                                              | Fill from the attribution tier; leave empty when the recipe is original                                                                                                          |
| `categories`                           | Array of text                                                                          | Course and cuisine tags                                                                                                                                                          |
| `nutritional_info`                     | Free text, not structured                                                              | Empty string when the recipe carries no nutrition values; otherwise one line, per serving, stated as text                                                                        |
| `created`                              | Timestamp text                                                                         | Export time (format not given in the reports; to verify)                                                                                                                         |
| `rating`, `difficulty`                 | Numbers                                                                                | Set `rating` to `0` and `difficulty` to an empty string: the plugin has no basis for either, and the converter writes these defaults                                             |
| `photo_data`                           | Base64-encoded JPEG                                                                    | Unset (`None`) unless the user provides an image; Paprika resizes photos to at most 2048 x 2048 pixels, so this is not an archive of originals (Perplexity)                      |
| `image_url`, `photo_hash`              | Remote image link; image checksum                                                      | Leave out unless an image is embedded                                                                                                                                            |
| `hash`                                 | Content hash used for sync                                                             | Listed in the plugin's field plan but named by none of the four reports (to verify); the converter sets it to the SHA-256 hex digest of the recipe JSON without the `hash` field |

Fields beyond the list above exist in real files (photo variants, flags, grocery state); the reports do not describe them, so the converter must not guess them.

### 3.3 Ingredients and sections

| Rule                    | Detail                                                                                                                                                                                                                                                                          |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Section heading         | A line ending in a colon, for example `Teig:`, becomes a heading in Paprika's ingredient list (documented; Claude, Perplexity). DeepSeek says no structured section model could be verified; the Paprika guide is the stronger source, and the default is to use colon headings |
| Line order              | Paprika recommends `quantity unit ingredient` (for example `1 cup milk`) so scaling and unit conversion work (documented)                                                                                                                                                       |
| Preparation note        | After the food, behind a comma (section 4)                                                                                                                                                                                                                                      |
| Heading outside Paprika | The colon convention is a Paprika rule only; never reuse it in JSON-LD                                                                                                                                                                                                          |
| Importers elsewhere     | AnyList treats ingredient headers; Mealie, Tandoor and others read their own conventions from the archive, and the reports do not say whether colon headings survive there (to verify)                                                                                          |

## 4. Ingredient-line conventions

Importers parse free text differently; these rules raise the hit rate everywhere and are the order `quantity unit food, note`.

| #   | Rule                                                                                                                                                                                                                                             | Reason / report position                                                                                                                                                                                                                                                  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | One ingredient per line                                                                                                                                                                                                                          | all reports                                                                                                                                                                                                                                                               |
| 2   | Order: quantity, unit, food, then a comma and the note: `200 g Mehl, gesiebt`                                                                                                                                                                    | Claude and Perplexity; Paprika's own guidance matches. DeepSeek puts the note in parentheses at the end (`1 onion (finely chopped)`). Default: comma, because it also matches the schema.org examples; parentheses are used only for alternatives that must not be parsed |
| 3   | A space between number and unit; standard unit abbreviations in the recipe's language (`g`, `kg`, `ml`, `l`, `EL`, `TL`)                                                                                                                         | Spaceless CJK and attached units fail (DeepSeek)                                                                                                                                                                                                                          |
| 4   | Decimal point and ASCII fractions in machine-read output (`1.5`, `1/2`, `1 1/2`); decimal commas only in text shown to people. The converter passes amounts through as written, so write them this way in the recipe file if the target needs it | Claude, DeepSeek, Perplexity. Unicode fractions (`½`) are often supported but test before relying on them; the default avoids them                                                                                                                                        |
| 5   | No quantities inside parentheses; alternative measures go into the note after a comma                                                                                                                                                            | Claude. A Tandoor release moved parenthetical alternatives into the note, so they survive only partly (single source, to verify)                                                                                                                                          |
| 6   | Ranges: one quantity plus the range in the note (`2 Eier, 2-3 je nach Grösse`); keep both bounds in the internal model. The converter does not rewrite ranges: they are exported as written in the ingredient line                               | Claude and DeepSeek; Perplexity wants both bounds kept and no silent midpoint, which the internal model satisfies                                                                                                                                                         |
| 7   | "To taste" lines carry no number: `Salz, nach Geschmack`                                                                                                                                                                                         | Perplexity; avoids a fabricated quantity                                                                                                                                                                                                                                  |
| 8   | Count and size stay apart: `2 Zwiebeln, mittelgross`; packages state count and size: `2 Dosen Tomaten, je 400 g`                                                                                                                                 | Perplexity (design)                                                                                                                                                                                                                                                       |
| 9   | Section headings are separate lines in the target format's own syntax, and absent from JSON-LD                                                                                                                                                   | section 3.3                                                                                                                                                                                                                                                               |
| 10  | Keep the original-language line; do not translate to help an English parser                                                                                                                                                                      | Perplexity                                                                                                                                                                                                                                                                |
| 11  | Where an app has an AI parser or a structured API, prefer it over text parsing for German content                                                                                                                                                | Claude, Perplexity; Mealie's NLP parser is English-trained, its AI parser keeps the source language                                                                                                                                                                       |

Test cases for the later converter, built to cover the awkward shapes: a plain metric line, a mixed fraction, a decimal volume, a range with a note, a canned item with a size, a no-quantity seasoning, a German spoon unit, a German decimal comma with a prepared potato, a Unicode fraction with a German unit, and a bare section heading. Check four things per line: displayed text, parsed fields, scaling, shopping-list aggregation (adapted from Perplexity).

### 5.1 How to choose a target for the user

| User has                                                                               | Recommend                                                                                             |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Paprika, AnyList, Cookmate, RecipeSage, or a Mealie or Tandoor server and wants a file | `.paprikarecipes`                                                                                     |
| Mealie                                                                                 | JSON-LD paste, or the Paprika archive for bulk                                                        |
| Crouton                                                                                | JSON-LD file or ZIP                                                                                   |
| Nextcloud Cookbook                                                                     | JSON-LD placed in the recipe folder or posted to its API; warn about quantity quirks                  |
| Tandoor                                                                                | Paprika archive for files; web import from the hosted HTML page; deeper integration waits for phase 2 |
| An app that only imports from a URL                                                    | HTML page with embedded JSON-LD, hosted somewhere reachable                                           |
| Mela, Recipe Keeper, KitchenOwl, ManageMeals, Grocy                                    | No plugin-written file works reliably: hand over the plain-text card or the HTML page and say so      |
| Nothing specific                                                                       | JSON-LD file, plus the Paprika archive on request                                                     |

## 6. Formats the plugin does not write

| Format                                                                                    | Why not                                                                                                                                                                                                                                                                                        | Where it matters                           |
| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Cooklang (`.cook`)                                                                        | Plain text with `@ingredient{qty%unit}`, `#cookware{}`, `~timer{}`, YAML front matter and `== Section ==` headings: good for a git-kept personal archive, but of the surveyed apps only Tandoor imports it (a single file, no images, no ZIP). Little reach for the effort                     | Users who keep recipes in a repository     |
| Mela (`.melarecipe`, `.melarecipes`)                                                      | JSON with `id`, `title`, `ingredients` (with `#` group titles), `instructions`, base64 `images` and more; a collection is a ZIP of these. Claude treats the vendor's file-format page as authoritative; Perplexity could not confirm a specification (conflict, to verify). One Apple-only app | Apple users; a candidate for a later phase |
| MasterCook (`.mxp`, `.mx2`, `.mz2`)                                                       | Legacy fixed-layout text and XML formats, imported by a few apps. `.mc2` and `.mcx` are cookbook storage files, not exchange formats (Perplexity)                                                                                                                                              | Legacy desktop users                       |
| Meal-Master (`.mmf`)                                                                      | Fixed-column legacy text format, 60-character titles; only Tandoor, Paprika and Cookmate import it                                                                                                                                                                                             | Old recipe archives                        |
| RecipeML, Open Recipe Format                                                              | No importer found in any surveyed app; treat as dormant                                                                                                                                                                                                                                        | None                                       |
| RezKonv, CookML                                                                           | German legacy desktop formats; Tandoor and Cookmate import them (Claude only; to verify). Not worth a writer                                                                                                                                                                                   | Users moving from old Windows tools        |
| App-native archives (Tandoor ZIP, Mealie backup, Nextcloud collection, Recipe Keeper ZIP) | Version-specific backups, not a single-recipe interface. Tandoor's archive must be imported as the whole ZIP, and Mealie's recipe export differs from its server backup                                                                                                                        | Migration only                             |

## 7. What to tell the user

| Situation                                              | Say                                                                                                                                                                    |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Recipe has ingredient groups and the target is JSON-LD | The groups are not part of the format: ingredients appear as one list; offer the Paprika archive or note the groups in the method                                      |
| Target is JSON-LD and the recipe has notes             | The notes (original amounts, conversions, serving tips) are not in the JSON-LD file; they stay in the Markdown file                                                    |
| Recipe has `signature` or `oven`                       | Neither format carries them unless the text already appears in a step; they stay in the Markdown file                                                                  |
| Target is a URL-only app                               | The app reads web pages, not files; offer the HTML page and explain it must be reachable by the app                                                                    |
| Ranges, "to taste", package sizes                      | Exported as written in the ingredient line; importers may misread a range or a package size, so check the first import                                                 |
| Nutrition present                                      | Values are per serving and appear as text in Paprika; some apps ignore them                                                                                            |
| No image                                               | The recipe is exported without one on purpose                                                                                                                          |
| Non-English recipe                                     | Importers may misparse units like EL or TL; check the first import and use the app's AI parser if it has one                                                           |
| App status uncertain                                   | State that app support changes quickly and that the research behind this reference last checked it on 1 November 2026; do not present that date as a check of your own |
